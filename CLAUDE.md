# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working in the OpenArtifact repository.

## What this is

OpenArtifact turns a small set of source files - one markdown file, an optional folder of HTML/SVG components, an optional CSS file and any images they reference - into one HTML page that renders itself in the browser. An artifact is made of **pages**: the markdown split on lines containing only `---`. The page carries the markdown, components and CSS verbatim as data blocks, so it reads as source to anyone who fetches it, loads the runtime `openartifact.js` from the server and references its images relatively, so it is served by `backend/server.py` at `/artifacts/<id>/`, presents in a browser and prints to PDF with Chrome headless against that URL. That page is the "artifact".

An artifact has a **type**, set in `artifact.toml` and orthogonal to `theme`, which decides how its pages are laid out: `deck` shows one 16:9 page at a time with navigation and prints one per sheet; `document` stacks fixed-width sheets, one per page, that print to A4; `page` is a continuous, fluid column like a Notion page. The type decides which stylesheets the runtime injects; the pages themselves are built the same way for every type. A page may open with a directive comment, `<!-- class: cover light; title: Welcome -->`, and `page_component` in `artifact.toml` names a component rendered around every page with `{{ CONTENT }}`, which is where headers, footers and counters live. Components take parameters as attributes and children between their tags; `{{ PAGE_NUMBER }}`, `{{ PAGE_COUNT }}`, `{{ PAGE_TITLE }}` and the uppercase keys of the `[context]` table are substituted everywhere outside code.

The repo has two halves:

- **`frontend/`** - the browser runtime, `openartifact.js`. This is the only thing with a JavaScript build step, and it exists solely to be loaded by the output page. All rendering (markdown, components, code highlighting, navigation, build steps, print layout, the per-type layouts) happens here, in the browser.
- **`backend/build.py`** - the builder, a library module with no dependencies beyond the standard library and no CLI. It does no rendering: it validates the inputs (including that every referenced image exists), writes markdown, components and CSS verbatim into an HTML page as data blocks and links `openartifact.js` by URL.
- **`chrome/`** - the chrome service: `chrome/pdf.py` drives Chrome headless against a served page URL, to print it or to screenshot one page of it, `chrome/server.py` exposes that as `POST /pdf/` and `POST /screenshot/`, and `chrome/Dockerfile` is the image with Chromium in it. The application server calls it for `/artifacts/<id>.pdf` and `/artifacts/<id>.png` through `backend/render.py`, and the `screenshot` MCP tool lets an agent see a page; the application image has no Chrome.
- **`backend/mcp_server.py`** - an MCP server for agents, built on `fastmcp` and `pydantic-monty`. `new_personal_artifact` and `new_org_artifact` create an artifact from markdown (in the caller's own space, private or public, or in their organisation, visible to it, optionally editable by it and optionally public) and build it; `set_access` changes that later and `fork` copies an artifact the caller can see, history included; `run_code` runs agent-written Python in a monty sandbox with the artifact's directory mounted read-write at `/artifact`, which is how the agent edits files; `build` calls `build.py` on that directory; `screenshot` returns one page as a PNG, so the agent can see what it made; `upload_url` mints signed URLs the agent `PUT`s local files to (`backend/upload.py`), so bytes never pass through a tool call; `list_artifacts` lists the caller's and the ones their organisation shares. Artifact identifiers are UUIDs. PDF export is not an MCP concern: it is the `/artifacts/<id>.pdf` URL on the server.
- **`backend/workspace.py`, `db.py`, `store.py`, `auth.py`** - storage and identity. Each artifact is a git repository, kept as a working tree in a local cache (the repository beside it, not inside it), serialised as a `git bundle` into an object store (local directory or S3) under an immutable key per commit, with Postgres holding each artifact's current head and the users / workspaces / artifacts tables. A workspace is the owner of artifacts (a user now, an org later), not a repository. Organisations (`organizations`, `organization_members`) come from Google Workspace accounts, and each artifact carries its placement and permissions (`organization_id`, `visibility`, `org_editable`), judged by the pure rules in `access.py`. The MCP endpoint is behind Google login (a static token for local development) through FastMCP's OAuth proxy; browsers sign in with the same Google client through `login.py` and a signed session cookie, and `server.py` applies the same rules to every artifact page and export. `pages.py` is the HTML shell for sign-in, access denied and the OAuth consent and error pages; `signing.py` the token scheme sessions, upload URLs and print passes share.
- **`backend/api.py`, `agent.py`, `chats.py`** - the web app's JSON API and its editing chat. `api.py` is the `APIRouter` under `/api` (who is signed in, the artifact list, creation, sharing, and the chat endpoints); `agent.py` is the pydantic-ai agent whose tools are this server's own MCP tools (`run_code` and `build`) called in-process as the signed-in user; `chats.py` stores one conversation per artifact per user. The chat streams in the Vercel AI SDK protocol through `VercelAIAdapter`.
- **`frontend/app/`** - the web app (React 19, Vite, Tailwind v4, `@ai-sdk/react`): `/` lists artifacts, `/edit/<id>` is the editor, a chat panel beside a live preview iframe of the artifact's page. Built to `frontend/dist/app/` and served by `server.py`; a second bundle beside the runtime, with its own tsconfig (`tsconfig.app.json`).
- **`backend/server.py`** - the FastAPI app that runs it all: the MCP server mounted at `/mcp/`, `openartifact.js` at `/openartifact.js`, and each artifact's page and media at `/artifacts/{uuid}/`, built on demand from the workspace checkout, with `.md`, `.zip` and `.pdf` exports beside it. `backend/main.py` is the entry point: it configures Logfire and serves `server.app`; `make dev` (uvicorn with reload) or `uv run backend/main.py` starts it.

The split is deliberate. The builder is thin enough to run anywhere Python 3.11 exists and to become a service later; the runtime is where the product lives.

### Where it is going

The service shape is now set: a FastAPI server hosting the MCP endpoint, with one git repository per artifact in an object store and Postgres. Next, in rough order: `git clone` / `push` of an artifact over smart HTTP (the repository is already there to serve), a GitHub backend (each artifact pushed as an orphan branch of one repo per workspace, using a GitHub App; its own repo or a folder of a chosen repo as later options), orgs owning workspaces with several members, forking an artifact (clone the repository under a new id with `forked_from` set), user-supplied themes, and browser login for private pages. The schema already leaves room for each (`credentials`, `forked_from`, an owner column to relax). `build.py` stays the importable, side-effect-free builder throughout.

### Rules that follow from this

- **The builder stays dependency-free and programmatic.** No package, no console script, no argparse, no `print`, no third-party Python imports in `build.py` or `chrome/pdf.py`; they return paths and raise `BuildError` / `ChromeError`. The project's runtime dependencies (`fastapi`, `uvicorn`, `fastmcp`, `pydantic-monty`, `logfire`, `asyncpg`, `obstore`) belong to the server modules, which import `build.py`, never the other way round.
- **Every change to an artifact is a commit.** File changes go through `workspace.edit()`, never by writing into a checkout directly; the commit, bundle upload and `head_sha` update happen together or not at all. Build output (`dist/`) is derived, excluded from git and rebuilt on demand.
- **One repository per artifact.** Locks, bundles and history are per artifact, so edits to different artifacts never wait on each other and an artifact's history is its own (the zip export and, later, `git clone` are a clone of it). The tree the sandbox mounts holds only the artifact's files: the repository sits beside it (`<cache>/<id>/git` and `<cache>/<id>/tree`), never inside it.
- **The agent is a user, not a service.** The editing agent calls the MCP tools in-process with no token; `auth.set_principal()` names the browser user for the run, inside the streamed generator (the body streams after the route has returned, and the in-process MCP session is created in that task), never around the route call. The browser sends only the new message each turn and the server supplies the stored history, because the adapter appends the request's messages to `message_history`. The toolset is entered per run, never at lifespan.
- **One cache directory per process.** The checkout cache is guarded by an in-process asyncio lock and the Postgres row lock; two processes sharing `OPENARTIFACT_CACHE_DIR` are not protected against each other.
- **The runtime does the work, the builder packages it.** If a feature can be implemented in `frontend/src/` it goes there. The builder only mirrors runtime logic where it lets a build fail early with a good error (see `validate_slides`).
- **Everything in the page is synchronous.** Headless Chrome prints at `load`, so the runtime must finish rendering before then. Never add async work to `main.ts`.
- **The toolbar is viewer chrome, not artifact content.** `toolbar.ts` appends one shadow host to `body`, outside `#root`; `build.py` and `server.py` know nothing about it, `@media print` hides it, and it uses `system-ui` and its own colours so it is the same on every artifact and the author's `styles.css` cannot restyle it. Fork and Edit will join it; nothing of it goes into the page `build.py` writes.
- **Output is served, not self-contained.** The page links `/openartifact.js` and references images relatively; `server.py` hosts the runtime at `/openartifact.js` and an artifact's images and fonts at `/artifacts/<id>/<path>`. Nothing is inlined as a data URI and `openartifact.js` is not copied next to the page. Opening `dist/index.html` from `file://` does not work and is not a goal.
- **A new artifact type is a stylesheet, not a fork.** Pages are built the same way for every type (`page.ts`); a type is how `main.ts` arranges them plus a stylesheet. Add the value to `TYPES` (build.py), `ArtifactType` (types.ts and mcp_server.py) and a `TYPE_STYLES` entry. Share `shared.css` and, for prose-like types, `prose.css`.
- **This is the library, not a deck.** Don't add brand-specific content, custom slides or example brand palettes here; those belong in user projects or in `examples/`. `examples/pennylane/` is a real brand deck kept locally for testing and is gitignored.

### Origin

Forked on 2026-09-30 from the `markdown-runtime` branch of [deckx](https://github.com/samuelcolvin/deckx), keeping its history. deckx shipped a Python package with a `deckx` CLI and a `deckx.toml` config file; here those are the single script and `artifact.toml`. The slide vocabulary (`.deck`, `DeckData`) was kept because it names the artifact, not the tool; the markdown file was `deck.md` until the `document` and `page` types arrived, and is now `main.md` for every type; the runtime bundle is `openartifact.js` because it names the tool.

DO NOT use the em dash "—" in source files or docs; always use a plain hyphen "-".

## Commands

Two toolchains. Use **pnpm** (never npm/yarn/bun) for the TypeScript browser runtime in `frontend/` and **uv** for the Python builder in `backend/`. `pyproject.toml` at the repo root holds the ruff / basedpyright / pytest config and the dev dependency group; uv installs nothing else. The pnpm commands run from `frontend/` (or `pnpm -C frontend ...` from the root); the uv commands run from anywhere in the repo.

```bash
pnpm -C frontend install              # install JS dependencies
pnpm -C frontend build                # both bundles: src/main.ts -> dist/openartifact.js (esbuild) and app/ -> dist/app/ (Vite)
pnpm -C frontend dev                  # the runtime bundle in watch mode
pnpm -C frontend app:dev              # Vite dev server for the web app on :5173, proxying the rest to :8765
pnpm -C frontend typecheck            # tsc --noEmit
pnpm -C frontend lint                 # biome check
pnpm -C frontend format               # biome check --fix

uv sync                               # create .venv with the dependencies and dev tools (uv run does this on demand too)
make pg-start                         # Postgres 18 in Docker (docker-compose.yml) at DATABASE_URL's default; `make pg-stop` stops it
make dev                              # the server on the host at :8765 with reload, dev token `dev` (OPENARTIFACT_DEV_TOKEN overrides)
make docker-up                        # build the image (Dockerfile) and run server and database with compose; docker-down, docker-logs
PYTHONPATH=backend uv run python -c 'from pathlib import Path; import build; build.build_html(Path("examples/starter"))'  # by hand
OPENARTIFACT_DEV_TOKEN=dev uv run backend/main.py     # HTTP server on :8765: MCP at /mcp/ (bearer token `dev`), openartifact.js, artifact pages
uv run ruff check                     # lint backend/ and tests/
uv run ruff format                    # format them
uv run basedpyright                   # strict type check of backend/ and tests/
uv run pytest                         # run tests/
```

The `Makefile` wraps these: `make install`, `make format`, `make lint`, `make test`, `make main` (all three, the default goal), `make build`, plus the `pg-*`, `dev` and `docker-*` recipes above; `make help` lists them.

`server.py` serves `frontend/dist/openartifact.js` and the web app from `frontend/dist/app/`, so run `pnpm -C frontend build` once after cloning or after changing anything in `frontend/src/` or `frontend/app/`.

**After every set of changes, before reporting work as done, run:**

```bash
make format
make lint
make test
```

If `format` modifies files, that's fine - those edits are correct. If `lint` or the tests report an error, fix it.

## Pre-commit hooks

The repo uses `.pre-commit-config.yaml` (biome format, typecheck, ruff, basedpyright, codespell, basic file hygiene). Use [`prek`](https://github.com/j178/prek) - a fast Rust reimplementation of `pre-commit` - rather than `pre-commit` itself:

```bash
prek install                 # install the git hooks (one-time)
prek run --all-files         # run every hook against the whole repo
prek run typecheck           # run a single hook by id
```

`pdftoppm` (poppler) is available for inspecting generated PDFs - render to `./tmp/` (gitignored), max 1800 × 1800 px. Headless Chrome with `--dump-dom` or `--screenshot` is the way to check the runtime without a browser session.

## Architecture

Two halves joined by the page's data blocks.

**Browser runtime (`frontend/src/`, bundled by esbuild to `frontend/dist/openartifact.js`)**

Paths below are relative to `frontend/`. `package.json`, `tsconfig.json` (the runtime), `tsconfig.app.json` (the web app, `jsx: react-jsx`), `vite.config.ts` and `biome.jsonc` live there too; the web app itself is described under the server section below.

- **`src/main.ts`** - entry. `readData()` assembles `ArtifactData` from the page's data blocks (`#artifact-config` JSON, `#artifact-markdown`, one `script[type="text/html"][data-component]` per component), reversing `encode_block` with `decodeBlock`; injects `shared.css`, the type's sheets (`TYPE_STYLES`) and `hljs.css` as `<style>` elements, then moves the page's own `<style id="artifact-styles">` (the user's CSS) to the end of `<head>` so it wins; splits the markdown with `splitPages` and builds every page with `buildPage`; a deck's pages go into `.deck-presenter > .deck` and navigation starts, a document's or page's into `.artifact-<type>`; last, `initToolbar` adds the viewer toolbar beside `#root`, unless the page is framed (`window.self !== window.top`): in the editor's preview or an embedding page the surrounding page is the viewer, and `reportPosition` tells it which page is showing instead. For a document or page artifact a `#N` hash scrolls the Nth page into view, so a screenshot of one page works for every type. Everything runs synchronously so the DOM is complete before `load` (headless Chrome prints at `load`). Never add async work here.
- **`src/split.ts`** - `splitPages`: splits raw markdown into `RawPage`s on `---` lines (fence-aware) and parses the leading directive comments (`class`, `title`; one or several comments, `;` or newline separated; a comment not starting with `key:` is left in the body). This is the source of truth for what a page is; `build.py` mirrors the scan to fail early.
- **`src/page.ts`** - `buildPage(page, index, total, data, config)`: renders the body into `div.page-body` (plus `prose` for the two prose types), computes `PAGE_TITLE` (directive, else first `h1`) and the page's context, wraps the body in the page component (`renderComponent` with the body as children; `{{ CONTENT }}` alone when there is none) inside `section.page[.classes]`, expands nested components and substitutes the context into the body's text. One code path for every type; `data-page-title` carries the title for `deck.ts`.
- **`src/render.ts`** - markdown-it (default preset, `html: true`) with highlight.js `lib/core` plus a curated language list.
- **`src/components.ts`** - `expandComponents(root, components, context)` replaces each `<component src>` tag, outermost first, with `renderComponent(source, attrs, context, children)`: the file's `<!-- params: ... -->` line is parsed off, one regex pass fills `{{ name }}` from the tag's attributes or the declared defaults (escaped), uppercase names from the context, and `{{ CONTENT }}` with a comment sentinel that is then replaced by the tag's live child nodes. Substitution happens on the string before parsing so placeholders work in attributes; nesting falls out of the loop. `unwrapParagraph` removes the `<p>` markdown-it puts around an inline tag. Images are untouched: relative `src` and CSS `url()` resolve against the page URL, which the server answers.
- **`src/substitute.ts`** - `PLACEHOLDER_RE` (mirrored in build.py), `escapeHtml`, `parseParams` and `substituteText(root, context)`, the tree walk that fills uppercase placeholders in the markdown's own text nodes, skipping `pre` and `code`.
- **`src/deck.ts`** - navigation: `#N` hash routing (1-indexed), keyboard, wheel, click delegation for `[data-nav="prev"|"next"|"first"|"last"]` elements a page component may contain, viewport scaling via `--page-scale`, `document.title` from the active page's `data-page-title`. Next/previous step through a page's build steps before changing page; shift + left/right jump a whole page. `initDeck` returns a `DeckController` (`position()`, `go`, `jump`, `onChange`) that the toolbar drives and observes; every navigation, including a step change, notifies its listeners. No chrome of its own: the viewer toolbar is `toolbar.ts`.
- **`src/toolbar.ts`** - the viewer toolbar: `initToolbar({title, type, theme, deck})` builds one shadow host (`#openartifact-toolbar`, `data-type`, `data-scheme` dark on a deck or a dark theme, light otherwise) appended to `body`, holding the title, for a deck previous / next, the counter and a full-screen toggle (also the `F` key) wired to the `DeckController`, a Download menu linking `<page path>.pdf`, `.md` and `.zip` plus a separated "View markdown" that opens the `.md` in a new tab (derived from `location.pathname`; omitted when the page is not at a `/.../` URL), and the brand, which opens the GitHub repository in a new tab. Once the page is up it fetches `<page>.json` (the one asynchronous thing in the runtime: viewer chrome, not page content) and `renderAccess` adds a visibility badge (Private / Org / Public, the detail in its tooltip), a Fork form button when `can_fork` (a POST to `<page>/fork`), and either a Sign in link (`login_url`) or an account button (the picture or an initial) opening a menu with the name, email, organisation and a Sign out form (a POST to `/logout` with `next`). `buildMenu` is the shared menu behaviour (open / close, roving focus over `[role=menuitem]`, Escape, outside click) behind both the Download and the account menus. Auto-hide: shown while the pointer is within 96 px of the top, over the bar, with focus inside or the menu open, and for 1 s after the pointer leaves that area, or until a click below it; a pointer over the page itself never shows it; shown for 2.5 s at load unless headless; pinned where there is no hover. The toolbar owns its keyboard isolation (`mousedown` does not focus its buttons, Space / Enter and the menu's arrow keys stop at the shadow root, wheel does not reach the deck) so `deck.ts`'s handlers are unchanged.
- **`src/steps.ts`** - in-page build steps. Elements with `data-step="N"` (and optional `data-step-end="M"`) get a `data-step-state` of `pending` / `active` / `done`; the page gets `data-step`. Print state is precomputed into `data-step-print`. All appearance lives in `deck.css`, never in JS.
- **`src/types.ts`** - `ArtifactData` / `ArtifactConfig` / `ArtifactType`, the contract with `build.py`'s `render_page`.
- **`src/styles/shared.css`** - the CSS variables, theme token assignments and reset every type loads. User `styles.css` overrides the variables. The `--slide-*` token names are the user contract and stay as they are.
- **`src/styles/deck.css`** - the deck: page geometry, the 16:9 `@page`, transitions, `.page-body` padding, page typography, the directive classes (`.page.cover`, `.statement`, `.light` (which reassigns the `--slide-*` tokens), `.tight`, `.wide`, `.large`), the opt-in layout helpers (`.row`, `.col`, `.cols-2`, `.cols-3`, `.shrink`, `.small-code`, `.center`) and the build-step rules. Everything is scoped to `.page` / `.deck-presenter`. No header, footer or counter: those come from the page component.
- **`src/styles/prose.css`** - typography for `.page-body.prose`, shared by document and page: the deck typography at reading sizes, the same `markdown-*` decorations, and print rules that keep headings with their text and blocks unsplit.
- **`src/styles/document.css`** / **`page.css`** - the two layouts: each `.page` a centred sheet at `--document-width` with an A4 `@page` and `break-before: page` between pages in print, or pages stacked in a fluid column capped at `--page-max-width`. Each sets the body background and its own `@page`. Note the clash of words: `.artifact-page` is the root of `type = "page"`, `.page` is one page of any artifact.
- **`src/styles/toolbar.css`** - the toolbar's sheet, placed inside its shadow root rather than injected by `main.ts`: the fixed glass bar, its two colour schemes, the hidden / visible states (`data-visible`, `:host(:hover)`, `:host(:focus-within)`, pinned under `(hover: none)`), the menu, and `@media print { :host { display: none } }`. `--oa-toolbar-height` in `shared.css` is the one value the artifact's sheets share with it (`document.css` and `page.css` leave room under `(hover: none)`).
- **`src/hljs.css`** - maps highlight.js token classes onto the brand variables, scoped to `.page, .prose`.

**Builder (`backend/build.py`)**

- A module, not a script: `build_html(directory, output=None, runtime_url='/openartifact.js')` is the entry point and returns the output path. There is no CLI; `mcp_server.py` and the tests are the callers.
- Loads and validates `artifact.toml` (`tomllib`; `type` in `TYPES`, `tabs` only for a deck, `favicon` a relative path that exists, `[context]` via `load_context`: uppercase keys, scalar values, no built-in names), reads `main.md` and splits it with `split_pages` (mirror of `split.ts`: `---` breaks outside fences, the directive comments; errors for an old `<slide .../>` marker, a `---` without a blank line before it, an empty page, an unknown or late directive), finds every component tag with `find_component_uses` (a regex scanner over the markdown with fenced and inline code blanked: attributes, children, nesting, the blank-line rules a block tag needs, self-closing and unclosed tags), loads each file once as a `ComponentSpec` (`.html` verbatim, `.svg` with its XML prolog stripped; `parse_params` reads the `<!-- params -->` line), and checks both directions with `check_component_file` and `check_component_use` (undeclared or unused parameters, missing required ones, children without `{{ CONTENT }}`, unknown uppercase names against `BUILTINS` plus the `[context]` keys; `check_body_placeholders` does the same for the markdown), checks every relatively referenced image exists inside the deck (`check_images`; nothing is embedded), rejects `</style` in the CSS (`check_styles`), and writes the `TEMPLATE` page: a `<link rel="alternate" type="text/markdown">` to the source (`main.md`, or `markdown_url` when the caller passes one: `server.py` and the `build` tool pass the `../<id>.md` export, and the head then also carries `MARKDOWN_EXPORT_NOTE`, a comment telling an agent that lands on the page to read the export rather than parse the HTML), the CSS as a live `<style id="artifact-styles">`, the config as JSON (`<` as `\u003c`), the markdown and each component as a data block (`<script type="text/markdown">` / `<script type="text/html" data-component>`) encoded with `encode_block`, and `<script src="{runtime_url}">`. `encode_block` escapes only the `<` of `</script`, `<script` and `<!--` (the sequences that move the HTML tokenizer out of script data) as `&lt;`, after doubling any pre-existing `&amp;` / `&lt;`; `decode_block` is its inverse and `main.ts` mirrors it.
- No third-party runtime Python dependencies, and no knowledge of where `openartifact.js` lives on disk: that is `server.py`'s concern.

**Chrome service (`chrome/`)**

- `chrome/pdf.py`: `print_to_pdf(url, pdf_path)` and `screenshot(url, png_path, width, height)` run Chrome headless (`run_chrome`; `find_chrome`: the macOS app bundle, then names on PATH) against the served page URL and return `Printed(path, stderr)`; a screenshot is the page in a window of that size (`--window-size`, `--hide-scrollbars`), and the URL's `#N` hash picks the page, which the page itself honours: Chrome's stderr is kept in every case, because a page that fails to load makes Chrome exit 0 without a file and report the reason (`Page load failed: net::ERR_...`) there alone. No paper flags: each type's stylesheet sets `@page` (16:9 for a deck, A4 for the others) and Chrome honours it. It takes a URL, not a file, because the page loads `openartifact.js` and images from the server. A missing Chrome, a non-zero exit or no file written raises `ChromeError` carrying the full command (to run by hand) and `.stderr`. `container_flags()` adds `--no-sandbox --disable-dev-shm-usage` when `CHROME_NO_SANDBOX` is set, which the image does. Standard library only.
- `chrome/server.py`: a FastAPI app with `POST /pdf/` (`{"url": ...}`, answers `application/pdf`), `POST /screenshot/` (`{"url", "width", "height"}`, 200 to 4000 px, answers `image/png`) and `GET /health/`; both renders go through `render()`: http(s) only, a Chrome failure is a 502 whose detail is the `ChromeError`, and the span (`chrome print to pdf` / `chrome screenshot`) gets the tail of Chrome's stderr as `chrome.stderr` on success and failure alike. It prints any URL it is given, so it is internal: compose keeps it on the private network and binds it to 127.0.0.1 only for `make dev`. `chrome/Dockerfile` installs the `chrome` dependency group (`fastapi`, `uvicorn`, `httpx2`, `logfire`) and Debian's `chromium`; `make chrome-dev` runs it on the host with the local Chrome. `chrome/main.py` is the entry point, mirroring `backend/main.py`: it calls `logfire.configure(service_name='openartifact-chrome')` and serves the app, so with `LOGFIRE_TOKEN` set the service's spans (the request, and a `chrome print to pdf` span around the subprocess, opened through the OpenTelemetry API so `server.py` stays Logfire-free) join the application's trace via the `traceparent` the instrumented httpx client sends. Chrome's own fetch of the page back from the app carries no trace headers and appears as a separate root span. `chrome` is a package imported from the repo root (`from chrome import pdf`), unlike `backend/`'s modules.

**Storage (`backend/db.py`, `store.py`, `workspace.py`, `config.py`)**

- `db.py`: `db_pool()` opens the asyncpg pool for the lifespan, `pool()` returns it. `migrate(conn)` applies `backend/migrations/NNNN_name.sql` in order under an advisory lock and records them in `schema_migrations`; versions must be consecutive. Tables: `users`, `credentials` (reserved for GitHub), `workspaces` (the owner), `artifacts` (uuid pk, `workspace_id`, `title`, `type`, `head_sha`, `forked_from`); `0002_artifact_repositories.sql` moved `head_sha` from workspaces to artifacts and does not convert earlier workspace bundles.
- `store.py`: `ObjectStore` over obstore with `get`/`put`/`exists`/`list`/`delete`, opened by `object_store()` from `OPENARTIFACT_STORE_URL`. Keys are immutable. A missing object raises `StoreMissing` (obstore reports it as `FileNotFoundError`).
- `workspace.py`: `checkout_path(id)` is the artifact's working tree in `config.cache_dir()` and `git_dir(id)` its repository beside it (a bare layout with `core.bare false`, addressed with `--git-dir` / `--work-tree` by `artifact_git(id, ...)`; `dist/` is excluded through `info/exclude`, so the tree has no git files at all). `sync_checkout(id, head_sha)` makes the tree match the head (fetching the bundle with `git fetch <file> main`, never `git clone`, then `reset --hard` and `clean`), deleting `dist/` when the head changed. `edit(id, message, create=None)` is the write protocol: artifact asyncio lock, `SELECT ... FOR UPDATE` on the row with a 60s `lock_timeout` (`ArtifactBusy`), or with `create=NewArtifact(...)` an `INSERT` of the row in the same transaction, sync, yield an `Edit` (`artifact`, `path`, `conn`, mutable `message`), then `git add -A`, commit if anything changed, `git bundle create`, upload to `artifacts/<id>/<sha>.bundle`, `UPDATE artifacts SET head_sha, updated_at`; any failure rolls back (the inserted row too) and the next sync repairs the checkout. `open_artifact(artifact)` is the read side. `clone_repository(id, dest)` clones the repository for the zip export (no remote, `dist/` excluded); call it under the lock. Row helpers: `get_artifact` (global, for public pages), `get_artifact_in` (scoped, for tools), `list_artifacts`, `import_directory`. Git runs via `asyncio.create_subprocess_exec` with a fixed env (`GIT_ENV`) and a Logfire span per call.
- `config.py`: `base_url()`, `cache_dir()`, `chrome_url()`, `internal_url()` and `secret_key()`, read from the environment on each call so tests can monkeypatch them.

**Auth (`backend/auth.py`)**

- `make_auth_provider()` builds the FastMCP `auth=`: `GoogleProvider` when `GOOGLE_CLIENT_ID` is set (needs `GOOGLE_CLIENT_SECRET` and `OPENARTIFACT_SECRET_KEY`, a Fernet key; the OAuth proxy's state lives in Postgres through `PostgreSQLStore` wrapped in `FernetEncryptionWrapper`, table `oauth_state`), else `StaticTokenVerifier` with `OPENARTIFACT_DEV_TOKEN`, else a startup error. Tests set the dev token in `conftest.py` before importing the server. The Google branch also calls `install_pages()`, which writes `pages.consent_html` and `pages.oauth_error_html` into FastMCP's modules in place of its renderers (the consent logic, CSRF tokens and cookies stay FastMCP's; a test pins the keyword arguments our page must accept). The proxy's routes (`/authorize`, `/token`, `/register`, `/consent`, `/auth/callback`, `/.well-known/*`) live inside the MCP app, which `server.py` builds with `http_app(path='/mcp/')` and mounts at the root, last, so they sit where the metadata built from `base_url()` advertises them; a test checks every advertised URL answers. The Google OAuth client needs two redirect URIs: `/auth/callback` (MCP clients) and `/login/callback` (browsers).
- `current_principal()` turns the verified token's claims (`sub`, `email`, `name`, `picture`, and `hd` via `hosted_domain()`) into a `Principal(user_id, workspace_id, email, name, picture, org_ids, organization_id)` via `upsert_user`, creating the user's workspace on first sight and, for a verified Google Workspace account (`hd`), the organisation (one row per domain, named by it) and the membership. Nothing is cached: membership is settled at sign-in and may change between calls. `load_principal(conn, user_id)` is the same principal for a browser session. `as_principal(p)` overrides it for code outside an MCP request (tests). Not authenticated is a `ToolError`.
- `access.py` is the pure rule set over an artifact's `workspace_id`, `visibility`, `org_editable` and `organization_id`: `can_view` (public, or the owner, or an organisation member when visible to it), `can_edit` (the owner, or a member when `org_editable`), `can_fork` (signed in and `can_view`), `can_manage` (the owner), and `check_access`, the human reason a combination is invalid (a personal artifact is private or public and never `org_editable`; an organisation's is visible to it or public). `Principal` and `Artifact` satisfy its protocols structurally, so it imports nothing.
- `login.py` is the browser door, an `APIRouter`: `GET /login` (the page), `GET /login/google` (PKCE verifier, `state` and the destination in the signed ten-minute `oa_login` cookie, then to Google with `prompt=select_account`, no offline access), `GET /login/callback` (state compared with `compare_digest`, the code exchanged and userinfo fetched with `httpx2` through `google_client()`, which tests stub; `upsert_user(..., hd=hosted_domain(info))`; the `oa_session` cookie, `user_id.expires.signature`, 30 days, HttpOnly, Lax, Secure on https; a 303 to the cookie's `next`, never the query's), `POST /logout`, and `POST /login/dev` only where Google is not configured (the dev user, optionally with an email and a Workspace domain, so organisations can be tried locally; the MCP dev token acts as the same user). `safe_next` keeps `next` a path on this server; `same_origin` (by `Sec-Fetch-Site`, else `Origin`) guards the POSTs on top of the Lax cookie. `current_viewer(request)` resolves the session, memoised on the request.

**MCP server (`backend/mcp_server.py`)**

- `FastMCP` server named `openartifact`, mounted into `server.py` (it has no entry point of its own). Its instructions, the text an agent reads before calling anything, are `backend/instructions.md`, loaded by `load_instructions()` with `{VIRTUAL_PATH}` and `{SKILL_URI}` filled in; edit the file, not the module. It also serves `skills/openartifact/` as an agent skill through FastMCP's `SkillProvider` (`SKILL_DIR`): the resource `skill://openartifact/SKILL.md` (`SKILL_URI`), a `_manifest` and a file template; the server instructions tell agents to read it. The Docker image copies `skills/` for this reason. The tool functions `new_personal_artifact`, `new_org_artifact`, `run_code`, `build_artifact` (registered as `build`), `upload_url`, `set_access`, `fork` and `list_artifacts` are plain coroutines so tests call them directly under `auth.as_principal`. Nothing in them blocks the event loop: the sandbox is `AsyncMonty` and the builder runs via `asyncio.to_thread`.
- The `AsyncMonty` worker pool is opened by the `monty_pool()` async context manager and lives for the app's lifespan. It is bound to the loop that opened it, so never create pools lazily or at import time. Tests use a `pool` fixture.
- `new_personal_artifact(title, content, public, type, theme, build=True)` and `new_org_artifact(title, content, org_editable, public, type, theme, build=True)` are the two ways an artifact is created, both through `create_artifact`: inside one `edit(create=NewArtifact(...))` it writes `artifact.toml` (`render_toml`, JSON string escaping is valid TOML) and `main.md` and inserts the row with its placement (`organization_id` None, or the caller's `principal.organization_id`; an error without one) and permissions (`visibility` private / org / public, `org_editable`), validated by `access.check_access`; then it builds unless `build=False`, for content that refers to components or images the agent has still to add. `public` and `org_editable` have no defaults: the permissions are the user's explicit choice. A build failure is returned as the `ToolError` but the artifact exists and is listed, for `run_code` to fix. `type` and `theme` are Literals kept equal to `build.TYPES` / `build.THEMES` by a test. `page_component` and `[context]` are not parameters; the agent edits `artifact.toml` for those.
- `resolve(artifact, edit=False)` applies the rules: an artifact the caller cannot see is reported as not existing (like a missing one), one they can see but not change says so and points at `fork`. `run_code` and `upload_url` resolve with `edit=True`; `build` is a read (it writes only derived `dist/`). `set_access(artifact, public, org_editable=False)` is the owner's (`can_manage`); `fork(artifact, org_editable=False, public=False)` copies through `workspace.fork_artifact` into the caller's organisation when they have one, else their personal space. `list_artifacts` prints the caller's own with an access summary, then the organisation's shared artifacts with their owners' emails.
- `run_code(artifact, code, inputs)` resolves the UUID within the caller's workspace (`resolve`; another workspace's artifact is reported as missing), mounts the directory read-write at `/artifact` inside an `edit()`, and commits even when the sandbox raised (message `run_code (failed): <id>`) before re-raising, so partial writes persist. Printed output and the trailing expression value are returned.
- `build(artifact)` runs `build.build_html` in a thread under `open_artifact`; output lands in the checkout's `dist/`, where the sandbox can read it, and the returned URL is `OPENARTIFACT_BASE_URL/artifacts/<uuid>/`. `screenshot(artifact, page=1)` (`can_view`) returns `render.screenshot` as a FastMCP `Image`, which pydantic-ai hands to the model as a `BinaryImage`; the page is built first if needed, a build error is the `ToolError`, as is a missing or failed chrome service.
- `upload_url(artifact, files)` takes `(path, size)` pairs and returns one URL per file, `PUT /artifacts/<uuid>/<path>?token=...`, for the agent to `curl -T` a local file to. It writes nothing itself. `backend/upload.py` holds the contract: `validate_path` (relative, normalised, no `.git*`, not under `dist/`), `validate_size` (10 MB cap), and `make_token` / `verify_token`, an HMAC-SHA256 over artifact, path, size and expiry (one hour) keyed from `config.secret_key()` (`OPENARTIFACT_SECRET_KEY`, else the dev token). Signing the size is what lets the server accept uploads without storing anything about the mint. The route is in `server.py`.
- The mount must contain only artifact data, never code the host executes; keep the cache directory off `sys.path`.

**HTTP server (`backend/server.py`)**

- `mcp.http_app(path='/')` mounted at `/mcp`. The app's `lifespan` enters FastMCP's lifespan (its session manager will not start otherwise), `db.db_pool()`, `store.object_store()` and `mcp_server.monty_pool()`, then runs migrations. The MCP endpoint is `/mcp/`.
- `/openartifact.js` serves `frontend/dist/openartifact.js` (`RUNTIME_JS_PATH`); every built page loads it from there. `/artifacts/{uuid}/` looks the artifact up with `load_artifact(id, request, edit=False)`, which applies `access.can_view` (or `can_edit`) to the session's viewer (`login.current_viewer`): a visitor gets `LoginRequired`, a signed-in user without access `Forbidden`, which the handlers turn into a 303 to `/login?next=<the page>` or the 403 page for a browser (`text/html` in `Accept` on a GET) and JSON 401 / 403 otherwise; then it syncs the checkout under `open_artifact`, builds `dist/index.html` if missing (a `BuildError` is a 422) and returns the HTML read under the lock; when the `Accept` header rates `text/markdown` or `text/plain` above `text/html` (`prefers_text`: a browser's list, `*/*`, `text/*` or no header all mean HTML, the page wins ties) it returns the markdown export instead, with `Vary: Accept, Cookie` and `Cache-Control: private` (`private()`) either way, as every artifact response has now that it depends on who asks. `/artifacts/{uuid}/{path}` serves images and fonts, and the source files (`SOURCE_EXTS`: `main.md` as `text/markdown`, `artifact.toml`, `styles.css` and `components/*` as `text/plain`) from the artifact directory after the containment and extension check in `contained_file`; anything under `dist/` is a 404, as is a non-UUID. The sources follow the page's access because the page already contains them, and `main.md` is what an agent should read instead of parsing the page. `PUT /artifacts/{uuid}/{path}?token=...` accepts an upload for a URL the `upload_url` tool minted (which required edit rights), governed by that token alone, not the session: `Content-Length` is required (411) and must be the signed size, the token must verify (403), the body is read in full before the workspace lock is taken, then the file is written and committed as `upload: <path>` inside `workspace.edit()`; the JSON answer carries the file's `sha256`. A path that resolves outside the artifact through a symlink is a 403, a directory in the way a 409, a busy workspace a 409. Beside the page, routed before the bare `/artifacts/{uuid}` redirect, sit `/artifacts/{uuid}.json` (placement, permissions, the organisation, the viewer, `can_edit`, `can_fork` and `login_url`: what the toolbar renders from; it too requires `can_view`), `POST /artifacts/{uuid}/fork` (same-origin, signed in, `can_fork`: `workspace.fork_artifact` into the viewer's personal space as private, then a 303 to the copy), and three exports: `/artifacts/{uuid}.md` is the markdown source behind a YAML frontmatter summary (`artifact_summary`: id, title, type and theme from `artifact.toml` where it parses, else the row; url, created_at, updated_at, and `files`, the source files from `source_files`, which skips `dist/` and `.git*`); `/artifacts/{uuid}.zip` is the artifact as a git repository under a folder named by the id: those files checked out at the head plus `.git` holding the artifact's history, a clone of the checkout by `workspace.clone_repository` into a temporary directory that is zipped after the lock is released; `/artifacts/{uuid}.pdf` builds the page (422 on failure), then has `render.pdf` ask the chrome service at `config.chrome_url()` to print `config.internal_url()/print/{token}/artifacts/{uuid}/` and relays the PDF (503 when no chrome URL is configured, 502 when the service is unreachable or fails: `render.RenderError` carries the status); `/artifacts/{uuid}.png?page=N` is one page as a PNG the same way (`render.screenshot`: the page number as the URL's hash, the window from `render.VIEWPORTS` per type), shown inline rather than downloaded. `render.py` holds what the routes and the `screenshot` tool share: the print pass (`print_token`, `print_url`, `verify_print_token`), `ensure_built`, `chrome_client` (the seam tests stub) and the two jobs. Chrome carries no session, so `/print/{token}/artifacts/{uuid}/` and `/print/{token}/artifacts/{uuid}/{path}` serve the same page and media by print pass instead: `print_token` is a five-minute `signing` token over the artifact id, minted for a viewer who passed `can_view`; relative media resolve under the prefix and `/openartifact.js` is absolute. Both downloads are named `{title} {sha}.{ext}` by `export_filename`: the `artifact.toml` title (else the row's), the 7-character sha of the last commit touching the artifact, characters file systems refuse replaced by spaces; `attachment()` sends it as an RFC 6266 `Content-Disposition` with an ASCII fallback and the UTF-8 name. The artifact lock is released before the chrome service is called: it fetches the page from this process, which takes the same lock. `/` returns a JSON index without artifacts; `list_artifacts` is per user.
- Configuration is by environment: `HOST`, `PORT` (default 8765), `DATABASE_URL`, `OPENARTIFACT_STORE_URL`, `OPENARTIFACT_CACHE_DIR`, `OPENARTIFACT_BASE_URL`, `OPENARTIFACT_CHROME_URL` (the chrome service; unset disables `.pdf`), `OPENARTIFACT_INTERNAL_URL` (this server as the chrome service reaches it, default the base URL; compose uses the alias `openartifact.internal`, because `app` is a Google TLD on Chrome's HSTS preload list and Chrome forces a bare `app` hostname to HTTPS), the auth variables above, and `LOGFIRE_TOKEN` to send telemetry.
- `Dockerfile` builds the application image (`make docker-up` builds and runs it): a node stage bundles `openartifact.js`, a uv stage installs the locked dependencies, and the final `python:3.14-slim` image adds `git`, runs as a non-root user and defaults the cache and local store to `/data`. Chrome is not in it; `chrome/Dockerfile` is the chrome image. `make docker-up` runs both images against the compose Postgres, the app on :8765 with the dev token (`OPENARTIFACT_PORT` moves the host port) pointed at `chrome` over the compose network, and `chrome` bound to 127.0.0.1:8766 for `make dev`. The compose database and the image's `/data` volume belong together: a `head_sha` whose bundle is not in the configured store is reported as such by `sync_checkout`.
- Observability: `main.py` calls `logfire.configure()`, `logfire.instrument_asyncpg()`, `logfire.instrument_monty()` and `logfire.instrument_httpx()` (every httpx/httpx2 client, so the call to the chrome service gets a span and carries the trace context); `server.py` never touches Logfire, so tests importing it send nothing. FastAPI's built-in telemetry and FastMCP's native spans pick up Logfire's global providers on their own, so do not add `logfire.instrument_fastapi` or `logfire.instrument_mcp`; they would duplicate spans. FastAPI is created with `telemetry={'auto_configure': False}` so it never adds OTLP exporters of its own.

**Web app API and agent (`backend/api.py`, `agent.py`, `chats.py`)**

- `api.py`: JSON only, for `fetch` from the app with the session cookie; `viewer_required` (401), `artifact_for(id, viewer, edit=False, manage=False)` (404 for missing or invisible, 403 otherwise), `mutation(request)` (403 unless `login.same_origin`). Routes: `GET /api/` (the index that used to be `/`), `GET /api/me`, `GET /api/configure` (`agent.configured_models()` and the default), `GET /api/artifacts` (`mine` and `shared`, each row with `can_edit` / `can_manage` / `owner_email`), `POST /api/artifacts` (`mcp_server.create_artifact`; only `type` is required: the title defaults to the type's placeholder in `agent.DEFAULT_TITLES`, the theme to `DEFAULT_THEMES`, the content to `STARTER_CONTENT`, the placement to personal and private; `placement`, `public` and `org_editable` as the tools take them), `PATCH /api/artifacts/{id}` (owner; `public`, `org_editable` and optionally `placement`, which moves the artifact between the owner's own space and their organisation; `access.check_access` then `workspace.set_access`), `GET /api/artifacts/{id}/chat` (the stored history as UI messages, consecutive assistant messages merged into one turn by `merge_turns`, serialised by alias), `DELETE` it, and `POST /api/artifacts/{id}/chat`: `VercelAIAdapter.from_request(sdk_version=7)`, the model id from the body's extra fields checked by `agent.check_model`, the stored history loaded, then `adapter.streaming_response(events())` where `events()` sets the principal, runs `adapter.run_stream(message_history=..., model=agent.resolve_model(...), deps=ChatDeps, conversation_id=f'{artifact}:{user}', usage_limits=UsageLimits(request_limit=40), on_complete=save)` and resets it in `finally`. A failed or stopped turn is not stored. When the turn is the conversation's first and the artifact still has its placeholder title (`agent.is_untitled`), `name_after_first_turn` runs `agent.suggest_title` (the tool-less `title_agent` on the same model, given the user's request and the first few thousand characters of `main.md`) and `workspace.rename_artifact` writes the title to `artifact.toml` (a `rename:` commit) and the row; a failure there is logged and the turn stands. The adapter accepts `application/json` only (415 otherwise), a second lock against cross-site posts.
- `agent.py`: `Agent(model=None, deps_type=ChatDeps, instructions=[PREAMBLE, skill_text()], toolsets=[toolset], name='openartifact-editor', capabilities=[WebSearch(max_uses=WEB_SEARCH_USES)])`; the `WebSearch` capability is the provider's own search tool (Anthropic's and OpenAI's both run through the gateway), executed provider-side, so it reaches the browser as a `tool-web_search` part with `providerExecuted` and costs no request of ours; `toolset = MCPToolset(mcp_server.mcp, max_retries=8).filtered(agent_tool)` keeps `run_code` and `build` (`AGENT_TOOLS`): the agent edits and rebuilds, it never creates, forks or shares. `skill_text()` is `SKILL.md` plus `references/styles.md` and `steps.md`; `about_this_run` names the artifact id to pass to every tool, the title, type and user, and the page the user has open (`ChatDeps.page`, from the chat body's `page`) so "this slide" means something; `AGENT_TOOLS` is `run_code`, `build` and `screenshot`, and the preamble says when to look. Models: `configured_models()` from `OPENARTIFACT_MODELS` (`id=Name,...`), else `BUILTIN_MODELS` when `PYDANTIC_AI_GATEWAY_API_KEY` (`GATEWAY_KEY`) is set: Claude Opus 5.5 and Sonnet 5.5 and the three newest OpenAI models, every one a `gateway/<upstream>:<model>` name so the Pydantic AI Gateway carries them all under that one key (`gateway/openai` is the Responses API); `default_model()` (`DEFAULT_MODEL`, `gateway/anthropic:claude-opus-5-5`, when configured, else the first), `check_model`, and `resolve_model`, the seam tests replace with a `FunctionModel(stream_function=...)` (`Agent.override` is a ContextVar and does not cross the TestClient thread).
- `chats.py`: `load`, `save` (upsert of `ModelMessagesTypeAdapter.dump_json(result.all_messages())` plus the model), `clear`; table `chats` from `0004_chats.sql`.
- Serving: `GET /` and `GET /edit/{id}` return `frontend/dist/app/index.html` (`APP_INDEX`, `Cache-Control: no-store`) to a signed-in viewer and raise `LoginRequired` otherwise; `/app/` is `StaticFiles` over `frontend/dist/app`; both and the router are declared before the root MCP mount.
- Frontend (`frontend/app/src/`): `router.ts` (two routes over `location.pathname`, `navigate`, `useRoute`), `api.ts` (typed fetch; a 401 sends the browser to `/login?next=`), the page the preview shows (the runtime inside the iframe posts `{type: 'openartifact:page', page, total}` to its parent on every navigation, `reportPosition` in `main.ts`; `Editor.tsx` keeps it, sends it with each chat message as `page` and reloads the preview at that hash), `pages/ArtifactList.tsx` (`Starters`, three buttons that create a deck, document or page in one click and open the editor; full-width rows for mine and shared with Edit and View), `pages/Editor.tsx` (header with the badge, the owner's access select over `AccessChoice` (`api.ts`: private, org, org-editable, public, public-editable, every choice but private placing the artifact in the organisation when the user has one; `accessFields` turns a choice into the PATCH body), Open page and reload, which also refetches the artifact so the title the first turn gave it shows; `Chat` left, `Preview` right), `chat/Chat.tsx` (`useChat({ id, transport, messages })` with `DefaultChatTransport` whose `prepareSendMessagesRequest` sends `messages.slice(-1)` and `body: () => ({ model })`; the preview reloads when a `tool-build` part reaches `output-available` and on `onFinish`; model picker from `/api/configure`; Stop; Clear), `chat/Message.tsx` (text through Streamdown, reasoning folded, tool parts as `ToolCard`, each run of provider-executed parts as one `ProviderToolGroup`), `chat/ToolCard.tsx` (folded card with a state-coloured edge; `run_code` shows its code and input names, `screenshot` the page fetched again from `/artifacts/<id>.png?page=N` since the bytes went to the model and not through the stream, `web_search` its query and, where the provider lists them, the pages found), `Preview.tsx` (iframe keyed by a version, reloaded at the current page's hash). Tailwind tokens in `index.css` match the toolbar palette; dark only.

The non-JavaScript `type` makes a `<script>` an inert data block whose content stays an exact string; the only escaping is `encode_block`'s. Images are not in the page. The page is served at `/artifacts/<id>/`, so relative image paths in the markdown, components and CSS resolve to `/artifacts/<id>/<path>`, which `server.py` serves from the artifact directory. The builder only checks that each referenced file exists.

## Page syntax in one paragraph

A line containing only `---`, with a blank line before it, ends a page, in every type; `***` is a rule inside a page. A page may open with `<!-- class: cover light; title: Welcome -->` (`class` adds classes to `section.page`, the built-in ones being `cover`, `statement`, `light`, `tight`, `wide`, `large`; `title` sets `PAGE_TITLE`, otherwise the first `h1`). `page_component` in `artifact.toml` names a component rendered around every page with `{{ CONTENT }}`; the built-ins `PAGE_NUMBER`, `PAGE_COUNT`, `PAGE_TITLE` and the `[context]` keys are substituted in the markdown and in components, outside code. Any element inside a deck page can carry `data-step="N"` / `data-step-end="M"` to take part in build steps. `<component src="Name.html" title="x">children</component>` needs its closing tag and, when it has children, a blank line after the opening tag and before the closing one; attributes fill the component's declared `{{ name }}` parameters, children fill `{{ CONTENT }}`; `.svg` components are inlined as markup. Uppercase `{{ KEY }}` placeholders come from `[context]` and the built-ins. See `SKILL.md` for the full reference.

## Code style

Add concise but thorough JSDoc-style comments on exported functions, and docstrings on Python functions. Comment any line of code that's complex or esoteric; otherwise let well-named identifiers speak. TypeScript is formatted by biome (single quotes, no semicolons, 119 columns); Python by ruff (single quotes, 120 columns).
